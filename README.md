# Server Keydesk · SSH 公钥助手

基于 [egoist/mygo](https://github.com/egoist/mygo) 的纯 Go 原生 Windows 桌面程序。全部界面使用 `mygo/ui` 绘制，不创建 WebView，不加载 HTML、CSS 或 JavaScript。输入 Linux 服务器地址、用户名、密码和别名，核对指纹后自动安装公钥，并验证后续密钥连接。

## 运行

双击 `Server-Keydesk.exe`。需要 Windows x64 和系统 OpenSSH 客户端。程序不需要 WebView2、Node、Bun 或 Go；编译源码才需要 Go 1.27.1 或更新版本。

启动时读取本机 SSH 配置，不会自动连接服务器。主界面显示完整服务器列表，点击顶部“添加服务器”打开密钥访问弹窗。默认窗口 1000×760，最小窗口 820×640。点击“检测”检查一台，点击“检测全部”检查列表中全部别名。程序不扫描局域网，也不能发现没有任何本地记录的任意服务器。

## 添加服务器

1. 点击“添加服务器”，在弹窗填写 IP/域名、用户名、密码、SSH 端口和一个未使用的英文别名。例如 `prod-web`。IPv6 不加方括号。
2. 点击“检查指纹并安装公钥”。应用在发送密码前先获取主机公钥指纹。
3. 通过云服务商控制台或其他可信渠道核对 SHA256 指纹，正确后确认安装。可在服务器可信控制台运行 `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` 查看对应 Ed25519 主机公钥指纹；其他主机密钥算法需查看对应文件。
4. 程序生成/复用应用专用密钥，用密码登录，将公钥追加到当前远程用户的 `~/.ssh/authorized_keys`。
5. 程序重新建立仅使用公钥的连接，执行验证命令，之后保存本地 SSH 别名，并使用系统 OpenSSH 再验证一次。
6. 成功后在任意能访问同一 Windows 用户 SSH 配置的终端或智能体中使用 `ssh prod-web`。

第一次安装支持直接连接的 Linux 服务器。服务器需要允许相应认证方式，并提供 POSIX `sh`、`awk`、`mkdir`、`chmod`、`cp`、`date`。不修改 sshd、不重启服务、不关闭密码登录、不改变 sudo 权限。

## 检测结果

| 状态 | 含义 |
| --- | --- |
| 密钥可用 | 系统 OpenSSH 已使用公钥认证并成功运行远程命令 |
| 尚未检测 | 有本地 SSH 别名，但没有检测记录 |
| 认证失败 | 此次非交互公钥认证未成功；可能是缺少公钥、用户名错误、密钥未解锁或服务端策略 |
| 网络不可达 | 超时、拒绝连接、DNS/网络问题；不能据此判断公钥是否安装 |
| 指纹待确认 | 本机 OpenSSH 尚未信任该主机，需先在可信终端核对并确认 |
| 指纹已变化 | 现有主机密钥记录不匹配或被撤销；应用不会自动覆盖 |
| 检测异常 | 其他配置、代理或远程命令错误，点击状态查看详情 |

已有服务器按其本来的 SSH 配置检测，包括现有密钥、SSH Agent、ProxyJump 和 ProxyCommand。加密私钥需要先在系统 SSH Agent 中解锁。已有服务器可检测任意已授权密钥，并不限定必须是本应用生成的密钥。首次经过跳板机/代理安装暂不支持。

历史结果标有检测时间，不代表服务器永久在线或权限不会变化。初次主机证书信任和已有别名的检测沿用系统 OpenSSH；新服务器密码安装的 Go SSH 后端读取用户默认 `known_hosts`，自定义信任文件或系统级主机 CA 需要单独核对首次指纹。

## 删除连接和重新创建密钥

服务器列表每行提供“检测 / 重建 / 删除”。

- **删除**：先展示将修改的本机配置文件，确认后删除该别名及检测记录，并备份原配置。保留私钥文件和远程公钥，避免影响共用这把密钥的其他连接或电脑。这不是撤销服务器授权。
- **重建**：填写当前服务器地址、用户名、端口和密码，先检查主机指纹；核对后勾选确认。程序为此连接生成独立新密钥，安装并验证成功后才切换本机配置。密码错误或验证失败时不替换原连接。
- 重建始终要求核对实际主机指纹；与默认 `known_hosts` 记录不一致时明确提示变化。自定义信任文件中的历史指纹需自行比对。只有核对新指纹并确认后才发送密码；新指纹保存在此连接的专用文件，不覆盖全局 `known_hosts`。默认信任记录中已撤销的主机密钥仍拒绝自动处理。
- 旧密钥与远程旧公钥保留。需要彻底撤销旧授权时，应核实 A、B 和其他服务器的共用情况，再单独清理远程 `authorized_keys`；本程序不自动执行此清理。
- 新密钥位于 `~/.ssh/keydesk/keys/<公钥标识>/id_ed25519`，可以继续通过“发送连接到其他电脑”迁移。
- 删除和重建的配置备份位于 `~/.ssh/keydesk/config-backups/<操作标识>/`，完成弹窗列出实际路径。导入连接的旧元数据归档为 `.retired-时间戳.bak`。已有智能体清单会同步刷新。

支持主配置及普通全局 Include 文件。复杂的条件 Include、跨文件 Host 配置、符号链接/目录联接，以及继承自定义 HostKeyAlias 的重建，会拒绝自动修改并提示手动处理。检查后的配置或 Include 列表变化时，必须重新检查。

页面采用紧凑布局，添加表单在弹窗中显示；主界面完整显示服务器列表，服务器较多时仅列表内部滚动。

## 本地文件位置

实际位置显示在程序“使用说明”中。默认使用当前 Windows 用户的 home：

- `~/.ssh/keydesk_ed25519`：专用 Ed25519 私钥。**无口令以支持自动连接**，Windows DACL 限制为当前用户访问；不读取或覆盖你原来的 `id_ed25519`。
- `~/.ssh/keydesk_ed25519.pub`：对应公钥，可以安装到多台服务器。
- `~/.ssh/config`：新增别名。每次写入前备份为 `config.keydesk-时间戳.bak`；新条目放在默认通配配置之前，原配置内容完整保留。
- `~/.ssh/known_hosts`：仅在你确认陌生主机指纹时追加记录。
- `~/.ssh/keydesk/status.json`：最后检测状态、服务器地址和用户名，不包含密码或私钥内容。
- `~/.ssh/keydesk/servers.md`：点击“导出智能体清单”时生成。

远程 `authorized_keys` 非空且需要追加时，先备份为同目录的 `authorized_keys.keydesk-时间戳.bak`。重复安装相同有效公钥不重复追加，原文件没有末尾换行时也能保留其内容。远程 `.ssh` 或 `authorized_keys` 是符号链接时拒绝自动修改。

密码仅供当次连接使用，不保存到配置、清单或日志。取消或完成后清空界面密码。操作记录仅保留在本次运行的界面内。不要把私钥文件提交到仓库或放进共享清单。

## 给不同智能体使用

### 将 A → C 的连接发送到另一台 Windows 电脑 B

本版本新增“发送连接到其他电脑”。如果 A 已经能通过 SSH 密钥登录 B，并且 A → C 使用的是本程序管理的直连密钥连接，可以把该私钥和所选 C 连接发送到 B，B 不用重新生成密钥，也不用再次输入 C 的密码。不会修改 C。

1. 在 **A** 打开程序，点击页面顶部的“发送连接到其他电脑”。
2. 选择源服务器 **C** 的本机别名，以及接收电脑 **B** 的现有 SSH 别名。
3. 填写在 B 上使用的 C 别名，点击“检查 A → C 与接收电脑 B”。这一步只验证连接和接收环境，不发送私钥。
4. 核对 B 的机器名、登录账号、用户目录、C 的地址及密钥指纹。勾选理解私钥访问范围后，点击“确认并发送私钥与连接”。
5. 只有明确确认后，私钥才通过现有 SSH 加密连接的标准输入发送；不会出现在命令参数、智能体清单或界面中。
6. 程序在 B 限制导入私钥的文件权限，保留 B 原有密钥和 SSH 配置，并从 B 验证连接 C。成功后可在 B 执行 `ssh 你选择的别名`。如果 B 已打开本程序，刷新本机配置即可发现导入连接。

**这是复制私钥。** 当前应用可能用同一密钥连接多个服务器，B 会获得这把密钥对所有已授权服务器的访问能力，而不只限于 C；界面只复制你选择的那个别名。之后撤销 C 上这把公钥会同时影响 A、B。请只发送到你信任的账号和电脑。

接收电脑 B 需要：Windows、可用的 SSH 服务和既有 A → B 密钥认证、Windows PowerShell 5.1+、系统 OpenSSH 客户端/ssh-keygen，以及到 C 的网络通路。B 无需安装 Keydesk。本功能不负责安装 SSH 服务或更改防火墙。

导入私钥位于 B 当前 SSH 登录用户的 `~/.ssh/keydesk/imported/<公钥标识>/id_ed25519`，不会覆盖 B 自己的 `keydesk_ed25519`。C 的已验证主机公钥会作为专用指纹文件传到 B；新别名固定使用该文件核对 C。现有别名若冲突会拒绝覆盖；相同的未修改导入记录可重复发送。

发送计划五分钟后过期，每个计划只能使用一次。源或目标 SSH 配置在检查后变化时，会停止发送。B 已保存密钥但无法连接 C，会明确显示“已保存但未验证”，不把网络问题当成安装失败。网络中断时 B 上可能已有部分导入文件，可检查后重新准备并重试。

当前只迁移程序管理的无口令私钥及直连 Linux C 配置，包括此前导入的应用密钥；暂不迁移个人加密密钥、只存在于 Agent/硬件中的密钥、证书、ProxyJump/ProxyCommand 或 Linux 接收端。B 的登录用户目录不可使用符号链接/目录联接进行导入。

### 导出服务器清单

点击“导出智能体清单”，在相应智能体的说明入口中加入类似内容（使用程序显示的真实路径）：

> 执行远程部署前，先读取本机 `.ssh/keydesk/servers.md`，按其中的 SSH 别名选择用户指定的服务器，并重新检查连接。部署操作遵循本项目的权限和确认规则。

本程序不自动改写所有智能体的全局说明文件。同一电脑、同一用户下的智能体可共用 SSH 别名；其他电脑、容器、云端智能体或隔离账号需要独立的密钥授权和配置。清单不是凭据，也不能绕过智能体自身的权限限制。

## 失败后的处理

- “公钥已写入，但验证失败”：检查服务器公钥认证配置、home 目录权限、账号限制。再次安装是幂等的。
- “远程公钥已安装并验证，但本机配置保存失败”：先修复本机配置文件权限/别名冲突，再重试，或用提示的专用密钥路径手动连接。
- 本机 `.ssh/config` 为符号链接时，程序保留该链接并拒绝自动写入。
- 配置锁目录 `.ssh/.keydesk-config.lock` 或远程 `.ssh/.keydesk-install.lock` 在进程异常中断时可能残留；确认没有安装任务在运行后再手工清理。

## 从源码构建

```bat
go mod download
build.cmd
```

开发启动：`go run .`。原生界面位于 `internal/nativeui`，通过类型化 Go 接口直接调用 `internal/desk` 后端。网络任务在后台执行，结果通过队列回到界面线程；关闭窗口会取消后台上下文。没有前端 RPC、本地 HTTP 控制端口或远程管理服务。界面布局、表单、弹窗和滚动均由 Go 实现。

正式构建通过 `build.cmd` 调用锁定版本的 `mygo build`，读取 `mygo.json` 并把 `resources/icon.png` 转换为 Windows 多尺寸图标资源，同时写入版本信息和 DPI manifest。窗口还显式使用同一 PNG 设置标题栏和任务栏图标。普通 `go build` 不会自动嵌入 EXE 文件图标；请使用上述构建入口。可执行 `python scripts/verify_windows_icon.py` 检查已构建 EXE 的图标资源。

依赖版本锁定在 `go.mod`/`go.sum`。如果默认 Go 模块代理不可达，可在你的构建终端设置可访问的 `GOPROXY`，不要为了构建修改 SSH 安全选项。
